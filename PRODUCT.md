# WikiBuild

## Register

product

## Users

Hashikome's owner, reading a local planning directory while building with agents.

## Product purpose

WikiBuild is a Hashikome experiment. For one or two weeks, use the existing Gr8r Studio interface as a read-only display
of workspace documents. Learn which views are useful before adding management
features. Open the app, select a directory, and read its projects and documents.

## Brand personality

Calm, structured, practical. Preserve the upstream application's visual language,
as explicitly selected by the owner; this experiment is not a redesign.

## Anti-references

Avoid an unrelated landing page, invented operational statistics, and controls
that suggest edits or uploads are saved when they are not.

## Design principles

- Existing files own the content. Reading never changes them.
- Show where information came from and where mapping is incomplete.
- Keep sample data visibly separate from connected workspace content.
- Prefer a small useful reading workflow over speculative management features.
- Keep public application code separate from private workspace content.

## Accessibility and inclusion

Retain the upstream system's keyboard focus, responsive layout and reduced-motion
support. Use semantic links, buttons, headings and tables. No special user-specific
accessibility requirements have been specified.
